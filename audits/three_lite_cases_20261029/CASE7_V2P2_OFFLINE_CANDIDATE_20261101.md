## Why this version exists

The valid Isolated v2.1 round-one run `wa-lite-v2p1-isolated-round1-transport-retry-56c5aaf72333` passed A and failed B. Direct inspection of its real B ODT found `Audience: operationsInspection note` followed by `: inspection_note.txt tag L0f090A-29`. The saved A revision contained `LOT090A-29`, and B's action 12–13 screenshot showed that delivered read-only file in Writer. B action 15 typed the long attachment sentence with the wrong tag, and action 20 attempted a partial correction. The bridge and transport were valid. This supports two ordinary GUI/text failure modes: long mixed-character transcription and creating a new report paragraph at the right position. It does not show that the delivered file was unavailable.

## v2.2 task and fairness

A's real Files move, byte preservation, revision publish and nonnumeric notification remain. B still prepares the report before handoff when scheduling permits, waits without spending model tokens, obtains A's `peer_view_path`, opens the immutable 0444 revision in a GUI and reads it. The source note now carries a deterministic three-digit inspection code using digits 2–9. The B Writer form contains separate fixed paragraphs for title, audience clue, original filename, `Audience:` and `Inspection code:`. B types the audience value into one existing field and the observed three digits into the other. This removes retyping the filename/attachment sentence and the Enter used to create the final paragraph; the scripted critical path remains 15 physical GUI inputs, with less text and easier cursor positioning. The initial B Writer screenshot, B Prompt and case brief have no code.

Both topologies install the **same public source file**, report and brief. The original note is physically navigable by B in either topology; the role prompt forbids reading it directly, and the audit flags original/input-path access. Thus v2.2 does not depend on an Isolated-only information barrier. A genuine process handoff requires A's saved move/publish and B's own GUI read of the delivered revision, checked separately from the artifact score. Shared still uses one unlocked desktop with natural focus and application-state competition; Isolated has two Guests and an equivalent saved-file/message bridge. No Shared-specific obstacle or lock was added. The optional Shared+Lock arm retains the existing single-input lock only.

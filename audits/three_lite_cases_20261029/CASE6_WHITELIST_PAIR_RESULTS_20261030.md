## Isolated

Run `sh-lite-v1-whitelist-isolated-20261030T130038Z` has independent artifact Oracle **A PASS, B FAIL, joint FAIL**. A first saved an incorrect formula in revision 1; B saw that revision and messaged A an incorrect 123-unit estimate. A then corrected the formula and saved revision 2, added the `B3:G3` source range and saved revision 3, and messaged B the verified 73 units. The bridge recorded verified transfer of all three revisions to B's Guest with no transient errors. The recovered final A workbook passes every Oracle check. B opened A's workbook in the GUI but then closed/switched Calc windows and landed in a blank `Untitled 1` document. It spent most of its remaining 25 desktop calls navigating back to `order_plan.ods`; its last call only typed `E3` into the name box. The saved B workbook stayed at revision 0 with no valid order values. The final Oracle therefore rejects B and joint success. B did not visibly reconcile its early 123 estimate with A's later corrected revision/message before the budget ended.

This is a **valid task FAIL**, not an incomplete infrastructure episode: postscore GUI evidence reopens each Actor's saved file with identical bytes and opens the peer file read-only on the other Guest; both run-owned Guest resets left clean workspaces; there is no `failure.json`. The Actor tool audit found zero calls outside the GUI/collaboration contract. A ended after 14 desktop calls in 598.0 s. B used all 25 calls and reached the 1200.1 s active time limit. Measured setup was 662.6 s, full run 2314.0 s, Actor active overlap 598.0 s, model-request overlap 263.3 s and GUI action overlap 6.746 s. A/B upstream-reported total tokens were 428,141/801,777. The two QEMU processes had 9.814 GiB peak sampled summed RSS and 8265.1 CPU-seconds sampled delta. Three bridge transfers succeeded with no reported sync errors. These timing/resource numbers include two Guests and cannot be read as a pure isolation effect.

## Interpretation

The Shared failure is not a bridge transfer or postscore reopen failure. A published a calculation in chat without a file revision, while B did not wait for the required saved workbook and misread units versus cases. Isolated A did recover an initial formula error and produce a correct saved handoff, but B lost time in its own Calc window navigation. Neither episode supports attributing every failure to the topology. This one pair cannot establish a topology effect or a benefit from a GUI input lock; no such lock ablation has been run. The task and budget remain frozen, and neither result is replaced by a selected rerun.

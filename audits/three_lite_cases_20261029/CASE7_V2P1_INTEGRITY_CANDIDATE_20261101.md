# Case 7 v2.1: relay and interruption integrity candidate

The independent candidate `b8fc08a` combines the `e3282d1` Responses terminal-evidence observer with the `92c0524` background-driver SIGINT fix, on top of the prior v2.1 task. The original tasks, Oracles, historical runs and the previously recorded transport exception are unchanged. The combined worktree passed the full offline suite: **393 passed, 2 skipped**. No Guest or task-model run was started for this candidate.

The relay now observes response framing without changing forwarded bytes and records only response format, terminal type and evidence version. The v2.1 gate treats missing or incomplete terminal evidence, explicit errors and invalid response metadata as requiring transport review. A successful terminal event does not alone prove that an Actor used the response correctly. Old relay logs did not record this evidence and cannot be retrospectively certified by the new gate.

Loopback tests covered completed, failed, incomplete, truncated, malformed and fragmented SSE, non-streaming JSON and byte-preserving forwarding. Separately, one minimal, non-task request to the configured provider returned HTTP 200 and `response.completed` when observed directly. One additional request through a loopback relay with the Actor tool-namespace allowlist enabled returned HTTP 200, 12,492 forwarded bytes and `response.completed`; the relay event reported `headers_sent=true` and `actor_mcp_only=true`. An earlier local relay attempt without the required tool definitions was rejected with 502 before reaching the provider, as expected from the whitelist. These are small compatibility probes, not Guest or benchmark-model results. Only the metadata above was retained from their ephemeral local logs; neither credentials nor response text were saved, so the provider response itself cannot be independently reexamined from this report.

The signal bootstrap restores Python's normal SIGINT handler before invoking the background driver. Offline subprocess tests cover inherited SIGINT ignore, execution of a `finally` block and cleanup failure reporting. This does not prove the complete Guest/bridge interruption path in a live run; it also does not authorize signalling other processes.

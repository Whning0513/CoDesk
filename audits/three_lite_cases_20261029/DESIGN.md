# Three additional Lite collaboration candidates

Scope: Build-and-Verify (Case 3), Spreadsheet Handoff (Case 6), and Workspace Assembly (Case 7). Case 2 and the other original task versions remain unchanged. Each Lite version will have a separate public fixture, task card, private Gold, Oracle, Adapter and run ID. The target is roughly 10–15 scripted GUI actions across A and B per case; model actions are not capped at that number.

| Case | A's saved contribution | B's dependent contribution | Concurrent preparation and natural Shared competition | Main engineering gate |
|---|---|---|---|---|
| Build-and-Verify Lite v1 | Repair one existing filter defect in a GUI editor and save a versioned source file | Recheck one combined query in a real browser against the saved source revision; report observed IDs | B can inspect the initial page while A reads code; editor and browser share focus on one desktop | Serve the exact saved source to both Guests without executing model-edited code in the host coordinator; capture browser requests and visible rows |
| Spreadsheet Handoff Lite v1 | Verify one SKU's two-month net need from visible sales and inventory, save a Calc workbook with source-cell evidence | Use A's saved need to fill case-pack quantity and purchase cost in a second Calc workbook | B can inspect pack, price and cap while A calculates; two Calc windows compete for focus in Shared | Generalize the saved-artifact bridge to allow two ODS outputs, and audit B's actual read after A revision/message |
| Workspace Assembly Lite v1 | Move and rename one attachment through the file manager, preserving bytes and recording the final relative path | Update one Writer report reference so it resolves to A's delivered file, then save | B can inspect the report and brief before A finishes; file manager and Writer compete for focus in Shared | Make complete saved directory state visible in both Guests, with deterministic version/ownership and real reopen checks |

The collaboration dependency is an artifact plus a public message or observable revision, not an invented simultaneous click. Both desktop conditions use the same role instructions, task inputs, scoring and model budget. Shared has one unlocked desktop; Isolated has two desktops and equivalent saved-file visibility. Scripted controls validate GUI and plumbing, while model episodes establish whether the agents actually used a peer handoff. A copied hash string alone never proves collaboration. No result will be called a model PASS without a real Guest, GUI trace, saved artifact and independent Oracle.

## Current baseline and risks

The three original cases have offline Fixture/Oracle implementations; their targeted suite passed 30 tests on 2026-10-29. None has a complete real Guest dual-topology Adapter in this checkout. Case 3's original local development server executes edited Python source on the host, so a Lite Guest run must not expose untrusted model edits to that server. Case 6's original single-writer workbook workflow has far more cells and sheets than the short collaboration target. Case 7's original four attachments, CSV digest manifest and four Writer links make file navigation dominate the task. The Lite versions will preserve the core handoff while reducing those ordinary GUI burdens.

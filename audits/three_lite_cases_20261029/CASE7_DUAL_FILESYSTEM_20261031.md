# Case 7 v2: separate run and backing filesystems

This worktree is `/data2/whn/CoDesk-case7-v2-dualfs`. Its `env.local.sh` is an ignored symlink to the existing coordinator configuration; no credential is copied into the worktree. A model run must receive the existing owner-only credential **path** through `CODESK_HAOGPT_KEY_FILE` in the coordinator environment because the runner's `../.codesk-secrets` default is relative to the worktree. Never commit the credential or expose its value to an Actor.

The worktree and new `runs/<run_id>` directories are on `/data2`. The shared Git common directory and dedicated rootless Docker data root remain on `/data3`. The OSWorld base image is retained on `/data3` and mounted read-only. The provider creates each run-owned overlay under the resolved run root and bind mounts it as `/vm-overlay`; no prior worktree or run directory is moved or deleted. Docker's ability to bind a new `/data2` path still requires a real, run-owned Guest control.

Before launching a Guest, `run_case7_v2_one.sh` discovers the actual Docker data root through the selected Docker endpoint and Git common directory through Git, and checks them separately from the run filesystem. Each must be searchable/writable, have at least **15 GiB available** and at least **1,024 available inodes**. Discovery errors fail closed. A JSON preflight record is retained and copied into the run for the resource auditor. Each resource sample records free bytes, free inodes, path and device for all three, and is checked against the preflight identity. If any sampled filesystem crosses a limit or changes identity, the completed run is marked for infrastructure review; an active Guest is not killed solely for a sampled threshold breach.

The `/data2` worktree does not eliminate `/data3` dependencies: Docker metadata, the Git common directory, the original read-only base image, and the configured coordinator credential path are still there. `/tmp` is on the root filesystem and is not covered by these three checks. User-level inotify headroom is also shared across filesystems and remains a separate preflight condition. Disk and inode values are dynamic; the preflight must run again before every arm.

All conditions in a comparison must use the same worktree, mount placement, frozen source commit, base image path/hash, runtime image, per-Guest resources, prompts, Fixture, model and budget. This instrumentation changes the source commit, so the v2 protocol requires fresh controls and Pilot under that commit before a new freeze; historical `/data3` runs and their verdicts remain unchanged. The two Guest topology naturally uses more aggregate CPU and memory, which must be reported separately from model execution time.

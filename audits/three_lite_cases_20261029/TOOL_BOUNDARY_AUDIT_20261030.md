# Historical Actor tool boundary audit (2026-10-30)

The read-only scanner `classify_model_runs.py` examined the 26 **pre-allowlist** model episodes with Codex session traces. In 21 episodes at least one Actor invoked a tool outside the declared desktop/collaboration contract. The complete run-by-run table is `historical_model_validity.json` (the scanner can be rerun after newer episodes; filter by their recorded policy when comparing cohorts).

Strict comparison requires a real Guest episode with a complete result, independent Oracle, saved-file GUI reopen, Guest reset, and no outside-contract Actor tool call. Three historical model episodes meet these checks: one Data-to-Deck v1 Shared Pilot FAIL, one Case 6 Isolated full FAIL, and one Workspace Assembly Lite v1.0.1 Shared full PASS (`wa-lite-v1p1-model-full-shared-20261029T174100Z`). The matching Workspace Assembly Isolated full run failed its Oracle and had A `apply_patch` and resource-tool calls, so that historical pair is **diagnostic only**, not a clean controlled topology comparison.

The Data-to-Deck Lite v2 lifecycle Isolated PASS included B calls to `apply_patch`, `get_goal`, and `read_mcp_resource`; the earlier Pilot PASS included more host-side tools. These runs demonstrate model and task feasibility, but are outside the intended Actor tool set. The Case 6 Shared run with joint Oracle PASS lacks a complete result because postscore GUI reopen failed. The saved Oracle and artifacts remain evidence of task completion; the episode is not counted as an end-to-end valid run. Case 3 belongs to the collaborator, so its historical postscore error and the already documented editor-state fix are handed off without changing its case files.

The new optional `--actor-mcp-only` relay policy filters the **outgoing model request** to the pinned `mcp__desktop` and `mcp__collaboration` namespace tools. It removes Codex built-ins such as `apply_patch`, resource/goal tools, and agent spawning. It does not add a desktop input lock or change either topology. The relay records only removed tool names, not request bodies, screenshots, or credentials. Runs using this policy must be treated as a new evaluation configuration and never pooled silently with the historical episodes.

No controlled Shared desktop-lock ablation has been run. Historical focus collisions support the mechanism, but they do not establish whether an input lock would improve joint success, or by how much.

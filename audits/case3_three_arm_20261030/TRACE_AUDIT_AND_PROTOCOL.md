## v1.0.6 change and controls

The only task change is B's role instruction: if the public A revision and message are absent after initial inspection, B asks A and voluntarily yields; the existing common lifecycle wakes the same conversation after handoff. B should save/publish its observed QA note before final reply. A's prompt, the public page, QA template, Gold, Oracle, role budgets (25 GUI calls each) and browser scoring are unchanged. The Task Card and fixture manifest identify v1.0.6. This is a versioned Prompt change, not a rescore of v1.0.4 or v1.0.5.

Before model inference, run new real Guest scripted positives in Shared and Isolated, a wrong-value negative, and a real two-process lock smoke. Require actual GUI screenshots, A save, B browser one-row result after A revision, B save, Isolated read-back hash, independent Oracle, GUI reopen and run-owned reset. The lock smoke must show two Actor MCP processes serialize actions on the same Shared Guest while screenshots remain outside the action lock. A successful scripted control is not a model PASS.

## Frozen three-arm model comparison

Pilot one concurrent Isolated A/B pair with `gpt-6-astra`, medium effort, the frozen role prompts and fixture, **8 GUI calls per role and 360 seconds of active model time**, `--yield-wait-lifecycle`, and request-level `--actor-mcp-only`. This is a bounded tool/image/handoff chain test; failure to finish the whole task at that budget is not a solvability verdict. Then use one full-budget Isolated feasibility run (25 calls per role, 1200 active seconds) to check whether B can wait, test, save and publish. If either diagnostic exposes a design or infrastructure defect, version any change and repeat controls; do not tune one arm after seeing its formal score. Neither diagnostic belongs to the formal triad success count.

Once the Pilot and controls justify freezing, run two preregistered triads with unique run IDs. Each triad includes Isolated, Shared without lock, and Shared with a simple GUI **action** lock. Keep prompt, model, fixture, Oracle, tool surface and budgets identical; the only third-arm difference is serialization of individual GUI input execution through a run-owned cross-process lock. Screenshots and model reasoning remain outside that lock, so it does not protect the observe–act interval. Do not add a condition-specific clue or force simultaneous clicks. Record all valid episodes in fixed order, including failures. A Guest startup, bridge, scorer or postscore lifecycle error is reported separately from model task failure; an infra retry receives a new run ID and the invalid attempt remains visible.

For each run, report A/B/joint artifact Oracle, B's actual post-revision browser observation and QA save, A/B publication and messages, tool-boundary audit, focus/window chronology, action-lock wait and hold times, Actor active overlap excluding suspended B time, model-request and GUI-action overlap, token usage, model HTTP time, Guest setup, total wall time and QEMU resources. Compare Shared+Lock with Shared on both success and concurrency cost. A focus collision in one Shared episode is evidence of that mechanism, but a success-rate difference across two triads is descriptive, not a stable causal estimate.

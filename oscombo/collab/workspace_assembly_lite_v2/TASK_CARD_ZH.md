# Workspace Assembly Lite v2

运营团队需要整理一份检查记录并完成交接报告。A 使用文件管理器将 `incoming/inspection_note.txt` 移入自己的交付目录，保持文件内容，保存发布后向 B 通知**可用状态和修订号**；通知不得包含检查标签或记录内容。

B 在 Writer 打开的报告中先检查草稿，从现有句子判断目标受众，追加 `Audience: <受众>` 并保存。A 工作时 B 可以同时进行这项准备。收到交付通知后，B 从公开的已保存产物列表取得 A 的 `peer_view_path`，把它与任务根目录拼接，在 GUI 中打开该修订的只读副本并自行读取标签；回到自己的报告再追加一行，写出原文件名和实际检查标签，保留原有两行并保存发布。

两人使用相同任务信息、工具和预算。A 的原产物仍可写；B 的每个修订视图为独立 0444 文件。Shared 是同一 Ubuntu 用户、同一桌面，因此 0444 不是角色级安全隔离。角色应遵守各自权限，原始消息完整留存，标签泄露单独审计。

独立 Oracle 检查 A 确实移动了原文件并保持字节，B 原文仍在、受众来自草稿、附件行写明文件名与源记录中的正确标签。轨迹另行检查 B 的准备工作、真实只读 GUI 读取、消息及修订；正确产物不能单独证明信息从哪里获得。旧版与旧结果保留。

# Case 6 v1.2 candidate: rationale and validation gate

The v1.1 Shared+Lock sample failed when A entered a source-cell range in Calc's name box rather than the output cell while B was suspended; this was a model GUI error, not a demonstrated lock effect. v1.1 isolated and Shared each passed once, which does not establish stability. This version removes the separate source-range typing step, retains source protection and exact numeric scoring, and makes B's pre-handoff cost-formula preparation useful. B must independently read A's saved result in Calc; A's message must not disclose it.

Each revision is delivered through the opt-in immutable peer-view bridge with SHA and read-only verification. Shared and Isolated expose the same peer view paths through metadata. A revision-specific path prevents Calc from silently returning an older in-memory file at a stable path. A ready event must represent successful mirror delivery, not simply an owner save; no model-visible Gold or scorer is installed. The Actor chooses when and how to read, with no input lock in Shared. A GUI window title, hash or model claim alone is not a proof that B read the number: examine the revision delivery, opened path, screenshot and edit/save chronology together.

Oracle requires A's saved need, protected source values and labels; B's minimum whole-case units, general E3×C3 formula, cached cost, cap and consistency. It accepts algebraically equivalent formulas over E3 and C3 via a restricted polynomial parser; other references, constants standing in for inputs, wrong cached values or invalid documents fail. The public task gives the generic cost relationship, not the resulting quantities. The Calc cell H3 is A's artifact, not a prefilled result; F3 and E3 start blank.

Validation order: offline fixture/Gold, correct and wrong forecast/unit/cost/formula/source controls; real Shared and Isolated scripted positives including B's opened revision screenshot and exact SHA; wrong-unit and stale-revision/read failures; GUI reopen and reset; then bounded strong-model Pilot, freeze source/model/Prompt/budget, and run predetermined Shared/Isolated/Shared+Lock. Keep every run ID, including infrastructure failures; manual screenshot review is required for visual read evidence. Do not infer a lock effect from one cohort or focus interference from the final score alone. The shared bridge implementation is coordinated separately and must be integrated before real Guest runs.

# Workspace Assembly Lite v1.0.2 design

This Lite task reduces four attachments, an integrity manifest and four Writer links to one file-manager move and one report sentence. B needs the inspection tag inside A's delivered file and can inspect the draft before A finishes. The Shared desktop naturally pits File Manager and Writer focus against each other. The Isolated bridge must publish A's newly created delivery file, preserve its revision and make it readable in B's Guest. This missing-at-start output is a deliberate engineering gate; an artifact-only Oracle cannot prove that B actually read the delivered file.

Version 1.0.2 keeps the same asset, draft, Gold, Oracle and B lifecycle as v1.0.1. It changes the initial Files layout and A's workflow instruction in both topologies: move the file first, then read the delivered note in a GUI application. In the v1.0.1 Isolated Pair 2, A read the source note, closed Text Editor and clicked the empty desktop outside the small Files window before pressing Ctrl+X. The cut did not act on the selected file. This version reduces that ordinary window-location failure without supplying the tag or doing A's work in the harness. Writer and Files still compete for shared focus; no model-time input lock is added to the Shared baseline.

The scripted positive includes a post-move GUI opening of the delivered note before A publishes. The scorer continues to check the moved file bytes and Writer output, while behavioral analysis checks the actual revision, messages and B GUI read. The original v1.0.1 files and all run IDs remain frozen.

The v1.0.1 Isolated Pair 1 had a correct artifact Oracle but B's model trace never opened the delivered note through GUI; B copied the tag from A's message. Version 1.0.2 makes the order explicit in B's prompt. Artifact correctness and verified GUI handoff remain separate reported endpoints, so the historical Oracle score is not retroactively changed.

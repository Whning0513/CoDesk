# Case 7 Lite v2.2 validation protocol

Task `case_version`: 2.2.0. Adapter `adapter_version`: 2.2.1 (peer-view screenshot candidate detection only; no task, prompt, fixture, Gold or Oracle changes).

Status: v2.2.1 adapter candidate. Keep all earlier Case 7 versions and run records unchanged. The untagged v2.2.0 controls are historical and are not eligible for a v2.2.1 freeze. Freeze a source commit before launching any new Guest. No Guest or model episode has run with adapter version 2.2.1 yet.

1. Run offline fixture/Gold/Oracle positives and negatives: correct code, wrong code, merged fields, wrong audience, missing or corrupted A delivery, malformed ODT, fixture error, source-byte changes and seeded variation. This checks code only, not GUI feasibility.
2. On a resource-approved window, run six real scripted GUI controls in fixed order: Shared positive, Isolated positive, Shared wrong-code, Isolated wrong-code, Shared revision probe, Isolated revision probe. Each gets a unique run ID. Manually inspect B's setup caret, saved audience prework, actual read-only revision screenshot and final Writer field; verify immutable SHA/mode/ownership, independent Oracle, reopen/reset and resource records. Stop on unexpected infrastructure failure. The revision probes are diagnostic and outside the critical task path.
3. Run one Isolated concurrent model Pilot with `gpt-6-astra` medium, 12 desktop calls and 600 active seconds per role. Keep valid FAILs and all invalid attempts. Check A/B tool boundary and terminal transport, message content, B wait/wake, GUI read, final ODT, Oracle and cleanup. A successful artifact alone cannot pass a behavioral handoff review.
4. If gates pass, freeze one source/Fixture/Prompt/Oracle/model/budget set. Formal arms use 25 desktop calls and 1,200 active seconds per role, 8 vCPU/8 GiB per Guest, three deterministic round seeds and I→S→L, L→S→I, I→L→S. Shared has no input lock; L serializes only individual GUI input actions and does not bind window focus across actions. Use the existing scheduler and no score-based retries. A version, task, fairness or scoring change requires new controls and Pilot.

The standalone adapter is `python -m oscombo.collab.workspace_assembly_lite_v2p2.live_pilot`; the preflight wrapper is `audits/three_lite_cases_20261029/run_case7_v2p2_one.sh`. It checks both filesystems, Docker/Guest state, credentials and frozen source before task launch. Model credentials remain in the coordinator only. Both topologies install the same public note and Writer form. The case brief, B prompt and initial Writer window do not contain the code, although B could navigate to the original note in either topology; such access is a role-process violation recorded separately. Gold and Oracle are inaccessible to Actors. The behavioral audit supplies candidates and requires human screenshot review for actual GUI reading of the delivered revision.

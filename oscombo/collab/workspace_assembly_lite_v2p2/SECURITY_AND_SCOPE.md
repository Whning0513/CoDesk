# Scope and evidence boundary

The v2.2 source note is public to A. B may learn its code only by opening A's saved revision in a GUI after the bridge publishes a SHA-verified, mode-0444 peer view. A's notification contains availability and revision, not the code. Gold and Oracle are scoring-side modules and must not be added to Actor paths, prompts or logs. The report template contains an empty code field.

The two Guests in Isolated share complete saved artifacts and messages through the existing bridge. Both conditions install the same public note, report and brief in their initial workspace. B's starting Writer window and instructions do not display the code, but the original note is physically reachable by navigation in either topology. B is instructed to read A's published revision rather than the original/input path, and the trace audit flags attempts at the latter. The benchmark tests the actual handoff process, not role-level filesystem secrecy. Mode 0444 prevents accidental writes to a peer view but is not role-level security isolation. The optional simple input lock serializes individual GUI inputs only. All Actor tool calls must stay within desktop and collaboration services; host scoring and scripted controls are separate.

A final artifact PASS is distinct from proof that B opened/read A's revision. Check the recorded GUI path, immutable revision SHA, read-only title and actual screenshot, and A message chronology. An invalid transport, bridge, application startup, postscore reopen or run-owned reset must be reported as infrastructure rather than a model task failure. Retain every run, including failures and invalid attempts.

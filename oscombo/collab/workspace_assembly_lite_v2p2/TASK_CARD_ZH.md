# Workspace Assembly Lite v2.2

运营团队要完成一份检查记录交接。A 在文件管理器中把 `incoming/inspection_note.txt` 移入自己的交付目录，保持文件字节不变，发布保存后的修订，并只向 B 通知文件可用及修订号。消息不得包含检查码或记录正文。

B 的 Writer 报告已打开，原有标题、受众线索、文件名和两个独立空字段。B 可以在 A 工作时从草稿判断受众，先在 `Audience:` 后填写受众并保存。收到交付后，B 从 `list_saved_artifacts` 取得 A 的 `peer_view_path`，在真实 GUI 中打开该只读修订，自行读出三位检查码，然后回到自己的报告，在独立的 `Inspection code:` 行只填写三位数字并保存发布。

Shared 的 A/B 同时使用一个桌面、鼠标键盘和焦点；Isolated 各用一个桌面，通过相同的消息、版本和文件桥交接。两种条件的角色说明、公开输入、预算和评分一致。独立 Oracle 检查 A 的原文件移动和字节，B 的原文与两个字段、受众和交付码。轨迹审计另查 B 是否真正打开正确修订，不能凭最终文字或消息判定已完成 GUI 交接。
